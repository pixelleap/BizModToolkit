## A3. 首页背景（card_bg）→ 并入「建造与装饰」

**现状**：2 个原子变体：壁纸展示（`opt_card_bg_0`）、建造与装饰展示（`opt_card_bg_1`）。

**建议**：在「建造与装饰」新增一个变体 **「首页展示」**，装 2 个 feat：

```
建造与装饰
├ 房间 (3 feat)
├ 地图修复 (3 feat)
├ 阶段解锁 (3 feat)
├ 装饰收集 (3 feat)
├ 家园 (3 feat)
└ 首页展示 (2 feat)   ← 新增
    ├ 壁纸展示        ← 原 opt_card_bg_0
    └ 建造与装饰展示   ← 原 opt_card_bg_1
```

**理由**：首页展示的两种形态都依赖玩家已有的内容（壁纸 / 家园装饰），和装饰进度绑在一起；单独一张卡只有 2 个 0-feat 变体，信息密度太低。

**备选**：并入「角色与外观」，或拆开（壁纸展示 → 相册与收藏，建造展示 → 建造与装饰）。**我推荐上面的整卡并入**，拆开会让变体多出一层、不好找。

**影响**：2 个 id 保留为 feat id，勾选随卡迁到「建造与装饰」。

**决定**：☐ 按建议并入建造与装饰　☐ 并入角色与外观　☐ 拆开分别并　☐ 不改

## A4. 图包商店（card_pack_shop）→ **保留独立模块（未执行合并）**

**决定**：用户明确「图包商店不能并入商城」→ **保留**，3 个原子变体原样不动。

保留原因（执行时确认）：图包商店是内容型售卖的独立入口，合并进通用商店会稀释两者的边界。

以后若要合并，本文的原方案仍然有效（降为「通用商店 / 图包货架」下的 3 个 feat）。

**现状**：3 个原子变体，都是「图包怎么卖」。

| 变体 | id |
|---|---|
| 限时特价 | `opt_card_pack_shop_2` |
| 捆绑特价 | `opt_mmumj7o922` |
| 单卖 | `opt_u2wrep8pxv` |

**建议**：在「通用商店」新增一个变体 **「图包货架」**，装 3 个 feat：

```
通用商店
├ 货币 (3 feat)
├ 道具 (3 feat)
├ 内容货架 (3 feat)
├ 直购 (3 feat)
├ 兑换 (3 feat)
├ 广告领取 (3 feat)
└ 图包货架 (3 feat)   ← 新增
    ├ 限时特价        ← 原 opt_card_pack_shop_2
    ├ 捆绑特价        ← 原 opt_mmumj7o922
    └ 单卖            ← 原 opt_u2wrep8pxv
```

**理由**：这三种都是"卖法"，不是"图包本身"，降成 feat 才符合「变体 = 一种货架形态、feat = 具体做法」的层级。通用商店本来就是货架容器，图包货架天然是它的一个变体。

**备选**：并入「礼包」（礼包是打包售卖，语义接近但会稀释「礼包」的含义）；或并入「限时特惠（黑市）」（它的「特价」变体和「限时特价」重叠，可能造成两处都能配特价，容易混乱）。**我推荐并入通用商店**。

**影响**：3 个 id 保留为 feat id，勾选随卡迁到「通用商店」。

**决定**：☐ 按建议并入通用商店　☐ 并入礼包　☐ 并入限时特惠　☐ 不改
