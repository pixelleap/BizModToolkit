# 变体 / feat 改造交接

当前版本：**v4.20.0**（2026-10-30）
线上：https://pixelleap.github.io/BizModToolkit/

## 现在的结构

43 个模块**全部**是「模块 → 变体 → feat」：

- `card.options[]` = 变体（一级），`variant.options[]` = feat（二级）
- 卡片带 `variantMode: true`；未带这个字段的旧数据按 legacy 语义渲染（兜底用，线上已经没有这种卡）
- 变体有独立启用状态：启用 ≠ 全选 feat，变体可以启用但 0 个 feat
- 变体之间**不互斥**，可以同时启用多个
- 0-feat 的变体是合法形态（原子变体），弹窗里只显示「已启用 / 未启用」

数据规模：43 模块 / **169 变体** / **433 feat** / 29 个原子变体。

## 选中语义

`project.optionSelections[cardId]` 是一个扁平 id 数组，同时装变体 id 与 feat id：

| 动作 | 写入 |
|---|---|
| 启用变体 | 加入变体 id |
| 停用变体 | 移除变体 id，并连带移除它的 feat |
| 勾 feat | 加入 feat id；父变体没启用时自动补上 |
| 全选 feat | 变体 id + 该变体全部 feat |
| 清空 feat | 只移除 feat，变体保持启用 |

**数据自愈**：`normalizeState()` 末尾会跑 `repairVariantSelections()`，老数据、外部导入、分享文件里「有 feat 没父变体」的情况都会自动补上；`importJSON()` 里也调了一次。仓库里的 `docs/data.json` 另有 `tools/repair-selections.mjs` 保证文件本身也是干净的。

## v4.20.0 做了什么

1. 全量切变体模式（43 张卡）。
2. 编辑器文案统一：一级 → **变体**，二级 → **feat**；检查器分区叫「变体 / feat」，按钮「＋ 添加变体」「＋ 添加 feat」。
3. 删除 23 个由旧正文自动生成、与真实变体重复的空壳变体（变体 192 → 169）。
4. 修 bug：
   - 删变体后选择里残留变体 id
   - 删掉变体最后一个 feat 会把变体整块删掉
   - 自检里「底座选项未全选」的断言在补父 id 后误报
   - `autoCategoryId()` 忽略变体自身 tags（33 个变体带 tags）
5. `lib/build.mjs` 的 webState 补 `variantMode`（否则 `npm run seed:data` 会把它抹掉）。
