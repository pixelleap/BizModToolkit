## 0. 判定规则

模组库要回答「**有哪些模块、每个模块有哪几种做法**」；单款游戏功能清单回答的是「**这个游戏要配哪些参数**」。按三条规则挑：

| 规则 | 特征 | 例子 |
|---|---|---|
| A｜参数值当变体 | 变体的子项是一串取值（1周 / 半个月 / 1个月），不是功能 | 挑战关 / 持续时长 |
| B｜入口·门槛当变体 | 变体描述「从哪进、什么等级能进、能做几次」 | 挑战关 / 进入方式、VIP 活动 / 参与等级 |
| C｜空壳变体 | 0 个 feat，只有一句配置说明 | 会员与订阅 / 低等级、高等级 |

参考项目的变体全是「模块形态」：挑战活动 = 挑战关 / X日挑战 / 连胜 / 限时闯关，没有「持续时长」这种参数。

## 1. A 类：变体级配置项（9 个）

| # | 模块 | 变体 | 现有子项 | 规则 | 建议 | 依据 |
|---|---|---|---|---|---|---|
| A1 | 挑战关 | 持续时长 | 1周 / 半个月 / 1个月 / 一直都有 | A | **删** | 四个子项是纯取值，活动周期属于配置 |
| A2 | 挑战关 | 进入方式 | 体力 / 广告 / 货币 / VIP免费 | B | **删** | 入口成本，已由「体力与次数」「广告接入与控制」覆盖 |
| A3 | 挑战关 | 挑战次数限制 | 空 | C | **删** | 0 feat 空壳 |
| A4 | VIP 活动 | 持续时长 | 1周 / 半个月 / 1个月 | A | **删** | 同 A1 |
| A5 | VIP 活动 | 参与等级 | 低等级VIP级以上 / 仅限高等级 | B | **删** | 门槛配置；人群定向在「人群专属活动」 |
| A6 | 累计活动 | 持续时长 | 1周 / 半个月 / 1个月 | A | **删** | 同 A1 |

## 2. B 类：整卡级候选（4 个）

这些卡整体更像「某一款游戏的功能清单」，参考项目里没有独立模块。

| # | 模块 | 现状 | 为什么像单款游戏功能清单 | 建议 | 处理后 |
|---|---|---|---|---|---|
| B1 | VIP 活动 | 2 变体（A4/A5 删完为空） | 参考项目没有；会员活动是「人群专属活动 / 会员」的一种 | **并入人群专属活动** | 卡 −1 |
| B2 | 累计活动 | 2 变体（A6 删完剩 1） | 参考项目没有；累计目标属于「任务与成就 / 累计目标」 | **并入任务与成就** | 卡 −1，变体 ±0 |
| B3 | 免费宝箱 | 3 个 0-feat 变体（免费 / 看广告 / 付费领取） | 参考项目里它只是「签到与周期领取」下的一个变体 | **并入签到**（新增变体「免费宝箱」，3 个变体降为 feat） | 卡 −1，变体 −2，feat +3 |
| B4 | 大关卡结构 | 4 个 0-feat 变体（线性 / 非线性·无限 / 单阶段 / 多阶段） | 是玩法结构设计，不是商业化模块；参考项目没有 | **移出模组库** | 卡 −1，变体 −4 |

## 4. 我的建议

1. **A 类全做**：这 9 个是明确的配置项，删掉不影响任何模块的表达力。
2. **B 类做 B1、B2、B3**：三张卡都是「某个玩法的一个切面」，并进去更符合模组库的定义。
3. **B4 大关卡结构单独再聊**：它不是配置项，是「关卡结构」这个主题；如果要留，建议至少把它标注成「非商业化 / 玩法结构」，不要和商业化模块混在一起。
